# ADR-0003 — State-шов: минимальный порт, solid-native дефолт, XState — опция

| | |
|---|---|
| **Статус** | accepted (user + оракул, 2026-07-12) |
| **Контекст** | диагноз по коду предка (capsule web-state + web-core engine) при проработке ит.1 шага 2 |

## Диагноз предка (проверено кодом, не памятью)

1. **«Вагон документов» бриджа**: каждая store-операция прописана ТРИЖДЫ —
   метод `bridge.ts` ↔ зеркальный редьюсер `create.ts` (`on: {SET_*}`) ↔ типы
   web-core. Фасад пух исторически (values/patch/updateComponent/tag-опции)
   и склеил три роли: системный протокол мутаций + user-data канал + удобства-запросы.
2. **XState вырожден**: все стейты пустые, переходы только синтетические
   `__GOTO_*__` (из любого в любой), UI-события мимо event-bus (ControllerProxy),
   lifecycle через createEffect. Реально используется ~10%: реактивный
   key-value store + строка `current`. FSM-семантику исполняют слои в userland —
   «слои сами задают флоу» (наблюдение user подтверждено).

## Решение

1. **Роли разделены**: системный протокол = закрытый малый `IStorePort` (kernel;
   user его НЕ расширяет — не растёт по построению) · user-data = одна
   generic-операция `update()` · FSM = `IStateApi` (current/set/matches,
   goto-модель) · удобства (pick/omit/match/values/patch + tag-алиасы) =
   store-ФАСАД logic-модуля ПОВЕРХ порта — растут в модуле, не в контракте.
2. **Порт минимальный** (`IStateAdapter.create(schema) → ILogicInstance`):
   `__GOTO_*`/`SET_*` — детали адаптера, в контракт не текут. Декларативные
   переходы/guards в канон НЕ возвращаем (v1): goto-модель остаётся; пересмотр —
   отдельным ADR по реальной нужде, не в вакууме.
3. **Дефолтный адаптер — solid-native** (`@omnifield/weber-state`): честный контракт кора
   покрывается Solid store + signal целиком; платить за state-machine-библиотеку,
   используя её как стор, — перестаём. Санитизация update-payload (aliasing-
   инвариант ADR 008 предка) сохранена в адаптере.
4. **XState — опциональный адаптер** (отдельный пакет, по мере нужды/спроса) —
   для настоящих FSM-фич (declared transitions, guards, inspector). Питч
   фреймворка меняется: «Logic: XState» предка → «Logic: schema-driven, state-
   начинка подменяема».
5. **Conformance-suite порта** (`runStateAdapterConformance`) — обязательный
   для ЛЮБОГО адаптера; XState-адаптер станет первым «как-юзер» тестом
   модульной механики: строится только через публичные контракты (user, 2026-07-12).

## Реактивность-контракт порта (уточнён реализацией)

- Чтения порта реактивны (геттеры в реактивных скоупах модулей).
- `registerComponent`/`unregisterComponent` меняют REF `components` верхнего
  уровня (coarse-подписка `onRegister` фаерит на регистрацию);
  `updateComponent`/`setProps` — fine-grained (value-патчи не шумят onRegister).
- `store.ctx` = ЧИСТЫЙ user-контекст (без `.data`-обёртки предка) — CC-10
  закрыт на шве; unwrap в ControllerProxy больше не нужен.

## Отвергнуто

- Открыть бридж для «регистрации операций» юзером — лечит симптом, раздувает
  протокол; корень был в склейке ролей.
- XState как обязательная база порта — платим за неиспользуемое; семантика
  `__GOTO_*` протекала бы в контракт.
